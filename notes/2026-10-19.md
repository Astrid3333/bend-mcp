# 2026-10-19

## Ciclo 1 — prueba de cada tool de Bend (classic + v2)

Objetivo: probar cada tool del MCP de Bend en las dos familias instaladas.

Estado inicial: `bend` classic 0.2.38 + `bend` v2 2.0.37 (`~/.bend/bin/bend`), ambas
usan el mismo workspace `/home/astrid/bend-mcp-workspace`; sin CUDA (`nvcc` ausente).

### Matriz de resultados (todas las tools)

| tool | classic | v2 | nota |
|---|---|---|---|
| check_install | ok | ok | v2 reporta `bend_family: v2` |
| list_programs | ok | ok | misma lista (workspace compartido) |
| write_program | ok | ok | v2 escribe en el mismo dir |
| read_program | ok | ok | devuelve código exacto |
| check | ok / ok-fail | ok / ok-fail | errores sintácticos salen con `ok:false` + stderr |
| run | ok (`rs`,`c`,`cu`→c) | ok (`v2`) | args e io probados (ver abajo) |
| compile | ok (`c`,`cu`→c) | ok (`auto`,`c`) | ver diferencia de salida |
| benchmark | ok (rs/c, cu saltado) | ok (clave `v2`) | mediana+mínimo por modo |

### Hallazgos verificados

1. **Sintaxis distinta por familia.** Classic acepta `def main(a, b):\n  return a + b`
   y rechaza `(def main () ...)`. v2 exige tipo de retorno (`def f(a: U32) -> U32:`),
   `import Base` para `U32`, y no acepta `return` clásico: el cuerpo es una expresión.
2. **v2: aplicación de tipo con paréntesis.** `IO` es un constructor `@-A:Type -> Type`;
   se escribe `IO(Unit)`, no `IO Unit` ni `(IO ())`.
3. **v2: args = argv con el script al frente.** `IO.args()` devuelve
   `[ruta_del_script, ...args_usuario]` (confirmado imprimiendo la lista completa).
4. **IO en v2 corre por defecto** en `bend_run`; el flag `io` se ignora con nota
   (`io_skipped`). En classic, `run-c` ya ejecuta IO y `--io` no existe: la tool lo omite
   con nota explicativa en vez de fallar.
5. **compile:** classic usa `gen-c`/`gen-cu` e **imprime el C a stdout** (no escribe
   archivo, no hay `output_path`); v2 usa `-o archivo.c` y sí reporta
   `output_path`/`output_bytes` (76 KB).
6. **Payload de compile enorme** (~67 KB, truncado por el límite de mensajes): emite el
   código generado completo. Oportunidad de mejora: resumirlo en el lado servidor.
7. **Fallbacks correctos:** `mode=cu` → `mode_fallback: cu->c: nvcc no disponible`;
   benchmark marca `cu: ok=false, skipped, reason: nvcc no encontrado`.
8. **Lambda v2 sin argumentos:** `() => ...` no parsea; usar `(u) => ...`.
   `IO.bind(A, B, m, f)` con `m: IO(A)` y `f: A -> IO(B)` (mezclar A/B da error de
   tipos claro, con contexto de variables).

### Lecciones

- Antes de `check` con un programa nuevo, calibrar la sintaxis contra un programa que ya
  corre en ese workspace: ahorra 3–4 ida y vueltas de errores de parser.
- `bend base` / `bend base --types` (solo v2) es la fuente autoritativa de la API de
  Base (p. ej. `IO.*`); consultarla antes de inventar firmas.
- El binario clásico y el v2 comparten nombre de programa y workspace: escribir con
  `bend2_write_program` y leer con `bend_read_program` funciona, pero el `check` de la
  familia equivocada fallará por sintaxis — no es bug, es familia.
